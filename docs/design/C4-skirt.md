# C4 裙摆方案

> 背景：报告 17/19 已证明「骨链 + 胶囊碰撞」不能解决裙摆穿腿——
> 骨点躲开了腿，裙片网格仍会被顶穿；形状匹配和加大余量都更差。
> 这里给出两条真正可行的路线。

## 路线 A：权重转移（已实现工具）

**目标**：让裙片由 `Q_*` 裙骨控制，而不是由腿/骨盆拖动。

**工具**：`tools/skirt_reweight.py`

```bash
blender -b scene.blend --python tools/skirt_reweight.py -- \
  --out scene_reweight.blend --materials 裙,裙内 --dry-run   # 先看影响面
blender -b scene.blend --python tools/skirt_reweight.py -- \
  --out scene_reweight.blend --materials 裙,裙内
```

**做法**

1. 按材质关键字收集裙片顶点；
2. 对没有 Q 骨权重的顶点，找最近的 1–2 根 Q 骨（点到骨段距离）；
3. 移除腿/骨盆权重（`--strip`），按反距离写入 Q 骨权重；
4. 保存新 .blend（不改拓扑/材质/形态键）。

**预期**

- 腿动不再整片拖动裙子；
- 配合 `physics --skirt`，裙摆才有独立摆动；
- 静态形状不变（rest 不变），但动画中的裙摆会与腿解耦。

**局限**

- 权重是几何最近邻，接缝处可能有轻微不自然，需要目视检查；
- 不解决“裙片网格比骨链胖”的壳偏移，极端抬腿仍可能穿；
- 需要 Blender 端验收（缩略图 + 渲染）。

## 路线 B：布料代理（未实现，设计）

**目标**：用真正的布料壳替代裙片变形。

**步骤**

1. 复制角色网格，只保留裙片面（按材质）→ `SkirtCloth`；
2. 腰部顶点（Q 根骨附近）设为 pin 组；
3. Cloth 参数：quality 5–8、collision distance 5–10 mm、
   structural 15–30、bending 0.5–2、mass 0.1–0.3、自碰撞先关；
4. 身体用**简化代理**（胶囊组合或低模），不要用 63k 顶点原网格；
5. 300 帧试跑，稳定后全片烘焙；
6. 导出：把布料顶点簇的质心映射回 Q 骨旋转（与 physics 的烘焙步骤相同），
   或保留独立网格仅用于渲染。

**风险**

- 薄片隧穿、抖动、自碰撞开销；
- 5640 帧 CPU 时间的量级（预计小时级）；
- 与形态键/材质的同步；
- 需要人工目视验收，不能只看数值。

## 验收（两条路线共用）

- 30 秒样本 + 全片抽样：`leg-skirt` 的 `high` 不高于原始；
- 可见性：最终机位下无可见穿透；
- 裙摆轮廓在转身/抬腿时没有“贴腿”或“炸开”；
- 与原始动作对比的 contact sheet 人工确认。

## 实测结果（2026-10-25）

- 权重转移 547/3,049 个裙片顶点；
- `leg-skirt` high：原始 17 → C4-A 17（持平）→ C4-A+物理 17，max 58.57→61.25；
- 视觉轮廓无变化，无接缝；
- **路线 A 不能解决穿模**，只证明“权重不是主因”。

## 决定

1. **先跑路线 A**：成本低、确定性高、可回滚（只改权重）；
2. 路线 A 仍不够 → 路线 B；
3. **不要再调** `skirt_shape_stiffness` / `collision_margin_units` /
   `use_mesh_radius`——报告 17/19 已证明是负结果。
