## 现象

手臂某一帧完全伸直、且手腕目标正好落在“肩—极向量”方向上时，
解出来的肘部落在肩腕连线上，**两骨长度不成立**；最终 FK 算回来的手腕
位置停在原地，间隙推离“推了但没效果”。

真实数据里表现为：`clearance_pushed` 有计数，但手腕位置没变。

## 复现

最小条件：

- 上臂 `L1`、前臂 `L2` 长度相等或接近；
- 目标距离 `d = L1 + L2`（伸直）；
- `pole`（源肘方向）与 `axis`（肩 → 目标）平行。

此时 `perp = pole - axis * dot(pole, axis)` 约为零向量，进入兜底分支：

```python
# 旧代码
if _dot(perp, perp) < 1e-9:
    perp = (axis[1]**2 + axis[2]**2, -axis[0]*axis[1], -axis[0]*axis[2])
```

对 `axis = (1,0,0)`，兜底结果是 `(0,0,0)`，归一化后仍是零向量，
于是 `E = base + 0`，肘部落回轴上。

## 根因

1. 兜底公式本身是错的：它不是“任意垂直向量”，而是叉积公式写残了；
2. 退化情况没有断言：`|E - S|` 应该恒等于 `L1`，但没有校验；
3. 两骨 IK 把“肘平面”当成默认存在的东西，没有显式处理共线。

## 修复

```python
if _dot(perp, perp) < 1e-9:
    # 取任意稳定的垂直方向，避免零向量
    ref = (0.0, 1.0, 0.0) if abs(axis[1]) < 0.9 else (0.0, 0.0, 1.0)
    perp = (
        axis[1] * ref[2] - axis[2] * ref[1],
        axis[2] * ref[0] - axis[0] * ref[2],
        axis[0] * ref[1] - axis[1] * ref[0],
    )
perp = _norm(perp)
```

## 为什么这么修

- 退化时肘平面本来就无定义，**任何方向都合法**；重要的是“垂直且稳定”，
  这样相邻帧不会因为参考向量翻转而抖；
- 用固定参考轴而不是随机，保证确定性（同一输入同一结果）；
- 没有选“把目标往回缩一点避开伸直”——那会改变动作，且治标不治本。

## 波及面排查（重点）

| 位置 | 是否受影响 | 说明 |
|---|---|---|
| `retarget_arms` 手腕位置 | 是 | 伸直帧全部受影响，修复后 wrist error 仍为 0 |
| 间隙约束 `_apply_clearance` | 是 | 推离后仍可能再次伸直 → 每次迭代都调用修复后的函数 |
| 腿 IK / `_clamp_to_reach` | 否 | 走的是另一套几何，没有极向量 |
| twist 恢复 | 否 | 只用轴角，不依赖肘平面 |
| 相邻帧稳定性 | 潜在 | 固定参考轴后方向稳定；跨参考轴切换（`abs(axis[1]) >= 0.9`）时可能跳变，需在动画里观察 |

**同类风险清单**（以后写几何代码时逐条过）：

- [ ] 任何“构造垂直向量”的代码，兜底是否可能为零？
- [ ] 有没有断言 `|E - S| == L1`、`|W - E| == L2`？
- [ ] 共线/重合/零长度输入有没有专门分支？
- [ ] 退化分支是否确定性、跨帧稳定？


## 教训

- **“推了但没效果”优先查 IK 解的合法性**，而不是加大推力；
- 几何兜底分支要么写对，要么显式报错，不要留一个“看起来能跑”的零向量；
- 单元测试要构造**退化**输入（伸直、共线、重合），正常姿态测不出来。
