# Bug 复盘库

> 目的：**报告只记结论，这里记过程和波及面。**
> 每个 bug 一份，写清楚“为什么错、怎么发现、改了哪里、还可能连累哪里”，
> 让后来的人（包括未来的自己）不用重踩。

## 一句约定

如果哪天你发现或修好了一个 bug——尤其是那种**不报错、但结果悄悄不对**的——
希望顺手在这里留一份短复盘。不用长篇大论，几段话写清四件事就够：

1. 现象和触发条件；
2. 根因（哪一行 / 哪个空间 / 哪个格式位）；
3. 怎么改的，为什么这么改；
4. **还可能连累哪里**（这一条最省后来人的时间）。

目的不是交作业，是让下一个人不用从零再查一遍。笔误、拼写这类就不必了。
模板见下方；编号递增即可。

```markdown
## 现象
## 复现

## 修复
## 为什么这么修
## 波及面排查（重点）
## 回归测试
## 教训
```

## 三条通用教训（目前）

1. **静默错误最贵**：崩溃会立刻被发现，错位/吞键/退化会一路带到成品。
   关键路径要有 round-trip、对拍或数值断言。
2. **空间要说清楚**：局部 / 父空间 / 世界，混用是这类 bug 的高发区
   （见 001、002、007）。
3. **统计量异常先怀疑口径**：数值大得离谱时，先问“我量的是不是同一个东西”
   （见 002、007）。
