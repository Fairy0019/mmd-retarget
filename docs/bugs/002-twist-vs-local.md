# 002 · twist 角度从世界旋转提取，把整条手臂的摆动算成了扭转

| 项 | 内容 |
|---|---|
| 日期 / 状态 / 严重度 | 2026-10-24 · 已修 · **中** |
| 发现方式 | 真实动作跑出来的统计量异常（均值 45.8°） |
| 修复提交 | `d37e694` |
| 相关报告 | `docs/reports/16-m1m2-complete.md` §1.2 |

## 现象

实现 `restore_twist` 后，真实动作（薇斯纳 + 恋爱循环）输出：

```
twist : 1 bones restored, mean 45.8 deg
```

源 VMD 里 `左腕捩` 的峰值只有 **6.3°**，按 `factor=0.5` 应该约 3°。
45.8° 显然不对，但程序不报错，只是“拧过头”。

## 根因

第一版从**世界旋转**里取轴角：

```python
q_w = qmul(parent_world_q, local_q)   # 父骨摆动 × 局部扭转
angle = 2*acos(q_w.w)
```

`parent_world_q` 包含整条手臂的摆动（这次动作里手臂大幅抬起/放下），
所以 `q_w` 的轴角主要来自手臂摆动，不是扭转。真正想要的扭转分量在
**局部旋转**里。

## 修复

直接用局部四元数取轴角，再把它投影到骨骼自身方向：

```python
q = sample_keys(keys, f, quat=True)
if q[3] < 0: q = (-q[0], -q[1], -q[2], -q[3])   # 规范化到 w >= 0
angle = 2 * acos(q[3])
axis = (q[0], q[1], q[2]) / sin(angle / 2)
sign = 1 if dot(axis, rest_dir) >= 0 else -1
twist = angle * sign * factor
```

应用到目标时，才需要把局部轴转到世界（`parent_t * axis`），
绕轴旋转后转回局部。

## 为什么这么修

- 局部旋转才是“这根骨相对父骨转了多少”，与父骨摆动解耦；
- 绕骨轴的分量不改变手腕位置，所以可以在 IK 之后安全叠加；
- `factor` 保留 0.5，符合 MMD 捻り的常见约定，也方便回滚。

## 波及面排查（重点）

| 位置 | 是否受影响 | 说明 |
|---|---|---|
| `restore_twist` 统计量 | 是 | 从 45.8° 降到 2.9°，与源峰值 6.3°×0.5 对上 |
| 手腕位置 | 否 | 轴角绕骨轴，理论上不动；测试断言位移 < 1e-9 |
| 手臂 IK | 否 | twist 在 IK 之后执行 |
| 其他“从世界旋转取角度”的代码 | **需要逐个检查** | 见下 |

**同类排查清单**：

- [ ] `forward_rotations` 的返回值是世界旋转，凡是用它做“增量/角度”的地方，
      是否应该改用局部？
- [ ] 统计量（mean/max 角度、位移）有没有物理上限？超出就应该报警而不是照单全收。
- [ ] 四元数的 `w < 0` 分支是否归一化？否则 `acos` 会取到补角。

## 回归测试

`tests/test_retarget.py::test_twist_keeps_hand_position`

- 源 twist 30°，目标应用后手部世界位置变化 < 1e-9；
- `mean_abs_deg == 15.0`（30° × 0.5），锁死口径。

## 教训

- **统计量是最好的哨兵**：45.8° 这个数字本身就在喊“口径错了”；
- 写“提取旋转”的代码时，先问一句：我要的是**局部增量**还是**世界朝向**？
- 测试里同时断言“位置不变”和“角度等于预期”，前者防几何错，后者防口径错。
