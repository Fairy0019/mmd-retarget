# 006 · root 的 0 位移键被吞，角色整体下沉 0.4 单位

| 项 | 内容 |
|---|---|
| 日期 / 状态 / 严重度 | 2026-10-23 · 已修 · **高** |
| 发现方式 | 逐帧位置 round-trip 断言（不是崩溃，是数值错） |
| 修复提交 | `2e8f5c2` 前后 |
| 相关报告 | `docs/reports/03-M0-canonical-writer.md` §5.2 |

## 现象

角色整体偏移 0.4 单位（约 3 cm），动作本身看起来正常，脚接触和滑步数据
全部偏了一截。没有任何报错。

## 根因

第一版只在“位移非零”时记录 root 位置键。`センター` 第 0 帧的位置键是
`(0,0,0)`，被当成“没有位移”丢掉了。writer 采样时只能把第一段非零位移
外推到第 0 帧，于是第 0 帧凭空多出 0.4 单位位移。

## 修复

先扫描出“有位移的骨”，对这些骨**保留全部位置键（包括 0）**：

```python
bones_with_motion = {name for name, keys in translations.items()
                     if any(any(abs(v) > 1e-9 for v in k[1:]) for k in keys)}
# 对这些骨，0 值键也写进 canonical
```

## 为什么这么修

- 0 是一个有意义的采样值，不是“空”；
- 判断“这根骨有没有动画”应该在**骨骼级**做一次，而不是逐键过滤；
- 保留全键后 writer 的线性插值与源一致，round-trip 误差归零。

## 波及面排查（重点）

| 位置 | 影响 |
|---|---|
| root 高度 | 整体偏移 0.4 单位，脚接触全偏 |
| 脚锁 | 锁定位置基于错误的脚世界坐标 |
| 滑步统计 | 数值不可信 |
| 其他稀疏通道 | **同类风险**：旋转通道是否也有“只写非单位四元数”的过滤？ |

**同类排查清单**：

- [ ] 所有“稀疏化/去重”逻辑，是否把“等于默认值”误当成“无键”？
- [ ] 0 位移、单位四元数、0 morph 权重，是否都保留？
- [ ] round-trip 是否做**逐帧数值**比较，而不只是“能读回来”？
- [ ] 偏移类错误有没有全局基准（例如脚底高度、root 高度）做断言？

## 回归测试

- 同骨架回写：25,973 帧，旋转误差 `3e-6°`、位移误差 **0**；
- 逐帧位置比较是专门的回归项（不是只看文件大小/骨数）。

## 教训

- **最危险的 bug 是不崩溃的数值 bug**；
- “默认值 = 无数据”是危险的等价，尤其在动画曲线里；
- 任何稀疏化都要有 round-trip 数值断言兜底，并且断言要逐帧、不是抽样。
