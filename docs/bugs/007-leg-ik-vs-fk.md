# 007 · 腿是 IK 驱动，用 FK 推脚踝最大错 61 cm

| 项 | 内容 |
|---|---|
| 日期 / 状态 / 严重度 | 2026-10-23 · 已修 · **极高** |
| 发现方式 | 与 Blender 逐帧对拍（`tools/blender_dump_pose.py`） |
| 相关报告 | `docs/reports/05-fk-validation.md` |

## 现象

用纯旋转 FK（`world_q = parent_q * local_q`）推算脚踝世界位置，和 Blender
里的真实 pose 对比：

- 身体骨中位误差 **1.2 mm**（够用）；
- 腿/脚踝最大误差 **61 cm**（完全不可用）。

接触段、脚锁、滑步统计全部建立在错误的脚位置上。

## 根因

MMD 的腿是 **IK 驱动**：`足ＩＫ` 的位移键决定脚的位置，腿骨（`足` / `ひざ`）
的旋转是求解结果，不是输入。用腿骨局部旋转做 FK，等于忽略了 IK 约束，
在深蹲、抬腿、大跨步时会把脚算到离谱的位置。

## 修复

- 接触检测、脚世界位置、脚锁统一改为**优先使用 `足ＩＫ` 的位移键**：

```python
foot_world = rest_head["左足ＩＫ"] + ik_translation(frame)
```

- 只有缺少 IK 骨时才回退 FK；
- 对拍验证：足 IK 目标 vs Blender 脚踝误差 **0.1–2.3 mm**。

## 为什么这么修

- IK 目标就是“脚应该在的位置”，这是动作的意图层；
- 旋转 FK 是结果层，用它反推意图属于本末倒置；
- 用 IK 目标还能天然处理“脚贴地”这类约束，脚锁不需要再猜。

## 波及面排查（重点）

| 位置 | 影响 |
|---|---|
| 接触段检测 | 段数从 355 变成 249，覆盖率从 34.6% 变成 67.4%（更准） |
| 脚锁 | 锁定位置必须用 IK 目标，不能用脚踝 FK |
| 滑步统计 | 之前 0.404 单位/帧的数字全部作废，重算为 0.1541 |
| 承重判断 | 用骨盆投影 + 脚位置，脚位置必须准 |
| 腿 IK 求解 | 目标来自 IK 键，链长用 rest，避免二次误差 |
| 手臂 | **同理**：手臂也有 IK 目标（如果有），当前动作是 FK，暂不涉及 |

**同类排查清单**：

- [ ] 所有“从骨骼旋转推位置”的代码，是否区分了 FK 骨和 IK 骨？
- [ ] 模型里哪些骨是 IK 驱动（PMX IK 链）？是否都走 IK 目标？
- [ ] 对拍是否覆盖极端姿态（深蹲、抬腿、大跨步），而不是平均姿态？
- [ ] 统计数字大幅变化时，先怀疑口径，而不是调参。

## 回归测试

- `tools/blender_dump_pose.py` + `tools/compare_fk.py`：17 帧 × 21 骨；
- 足 IK 目标误差 0.1–2.3 mm；
- 接触段/脚锁用真实 IK 轨迹重算。

## 教训

- **先对拍，再开发**：M1 的脚锁如果建在错误 FK 上，后面全部白做；
- 平均误差会骗人：身体骨 1.2 mm，腿 61 cm，必须分部位看 p95/max；
- MMD 里“看得见的骨”和“驱动动作的骨”常常不是同一根。
