# 003 · PMX 骨骼 flags 位错位，付与/轴固定全解析错

| 项 | 内容 |
|---|---|
| 日期 / 状态 / 严重度 | 2026-10-23 · 已修 · **高** |
| 发现方式 | 真实 PMX 解析时字段长度对不上 |
| 相关报告 | `docs/reports/02-M0-pmx-skeleton.md` §1.2 |

## 现象

解析真实 `薇斯纳.pmx` 时，到 `左目`（flags `0x011A`）处开始错位：
后面本应 6 字节的字段被当成别的长度，骨骼表整体偏移。

## 根因

网上不少 PMX 说明把 bone flags 写成了：

```
0x0040 回転付与 / 0x0080 移動付与 / 0x0100 軸固定 / 0x0200 ローカル軸
```

按这张表，`0x011A` 会被判成“轴固定 + 局部轴”，于是走错分支、读错长度。
实际（以 MMD Tools 的 `Bone.load` 为准，并用真实文件验证）是：

```
0x0100 回転付与
0x0200 移動付与
0x0400 軸固定
0x0800 ローカル軸
0x1000 物理後変形
0x2000 外部親
```

## 修复

按真实位表重写 flags 解析，并用真实文件回归：550 根骨、4 条 IK 链、
46 根轴固定骨全部与 MMD Tools 对齐。

## 为什么这么修

flags 决定**后续字段是否存在**（付与、轴固定、局部轴、外部亲、IK 链），
不是“读错一个布尔”这么简单——错一位就会连环错位。必须以参考实现为准，
不能以二手文档为准。

## 波及面排查（重点）

| 位置 | 影响 |
|---|---|
| 骨骼解析长度 | 错位后整张骨骼表不可信 |
| 付与/轴固定/局部轴 | 影响 rest 朝向与 IK 链判断 |
| `skeleton_profile.limits` | IK 链解析错误 → 膝盖限位缺失 |
| `retarget` 的手臂起点 | 肩/腕 rest 若错，IK 全部偏 |

**同类排查清单**：

- [ ] 所有“位域/枚举”常量是否与参考实现逐位对过？
- [ ] 解析器有没有“字段长度断言 + 总偏移检查”？
- [ ] 真实文件回归是否覆盖了带各种 flags 的骨骼（本例 46 根轴固定）？
- [ ] 二手文档与参考实现冲突时，永远以能跑通真实文件的为准。

## 回归测试

- `tests/test_pmx.py`：最小/完整 PMX、附加 UV、付与/轴固定/局部轴/外部亲、IK 链；
- 真实 PMX 解析：550 骨 / 63k 顶点 / 0.35 s，与 MMD Tools 对齐。

## 教训

- **格式文档会错，参考实现不会**；拿真实文件对拍是唯一可靠验证；
- 位域错误往往不崩溃，而是“后面全错”，所以解析器要有偏移断言；
- 看到某根骨的 flags 是 `0x011A` 这种组合值时，先停下来手工推一遍。
