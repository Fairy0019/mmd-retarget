# 004 · VMD 骨名用 0xFD 填充，按 NUL 截断会带上乱码

| 项 | 内容 |
|---|---|
| 日期 / 状态 / 严重度 | 2026-10-23 · 已修 · **中** |
| 发现方式 | 字节级 round-trip 对比（第三方 VMD） |
| 相关报告 | `docs/reports/01-M0-vmd.md` §3 |

## 现象

`センター` 解码成了 `センター`（尾部多出半角片假名），
骨名匹配不上，动作静默丢骨。

## 根因

VMD 的名称字段是 15 字节定长，常见用 `0x00` 填充，但第三方导出器会用
`0xFD` 填充。`0xFD` 在 CP932 里是合法的半角片假名，不是 NUL，所以
“找 `\0` 截断”对它无效，尾部字节被当成正常字符解码。

## 修复

解码前同时去掉尾部 `0x00` 与 `0xFD`：

```python
raw = raw.rstrip(b"\x00").rstrip(b"\xfd")
name = raw.decode("cp932", errors="replace")
```

写回时按原填充风格或统一 NUL（当前统一 NUL，字节级 round-trip 对
`0xFD` 样本用原始 padding 保留）。

## 为什么这么修

- `0xFD` 在名称里没有语义，只是填充；
- 先 `rstrip(0x00)` 再 `rstrip(0xFD)`，可以处理混合填充；
- 不能全局 replace（名称中间理论上可能出现该字节），只裁尾部。

## 波及面排查（重点）

| 位置 | 影响 |
|---|---|
| 骨骼名匹配 | 名字带尾巴 → 语义映射失败 → 动作丢骨 |
| morph 名 | 同样 15 字节字段，同一 bug |
| 相机/灯光名 | 同样字段布局 |
| round-trip 写回 | 填充风格变化会影响字节级比较 |

**同类排查清单**：

- [ ] 所有定长字符串字段（骨名、morph 名、模型名）是否都做了双填充处理？
- [ ] 解码用了 `errors="replace"` 而不是直接抛异常，是否会把格式错误藏起来？
- [ ] 字节级 round-trip 测试是否覆盖第三方样本（不只是自己写的文件）？

## 回归测试

`tests/test_vmd.py` 覆盖 `0xFD` 填充样本；真实第三方文件字节级往返一致。

## 教训

- **定长字段的“填充字节”不是协议的一部分，是习惯**；解析要宽容，写回要一致；
- 编码问题最喜欢“静默丢数据”，必须在名字匹配处加覆盖率告警（本次后加了
  `mapped / unmapped` 统计）。
