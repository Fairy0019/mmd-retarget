# 阶段报告 05 · FK 对拍与接触检测修正

- 日期：2026-10-23
- 范围：`tools/blender_dump_pose.py`、`tools/compare_fk.py`、
  `canonical.forward_positions` / `detect_contacts`
- 结论：纯 Python FK 对身体骨**够用**（中位误差 1.2 mm），但对 MMD 的
  **IK 驱动腿完全不适用**（最大 61 cm）。接触检测已改为优先使用
  `足IK` 目标位置，误差 0.1–2 mm。

---

## 1. 为什么要对拍

M0 的接触检测假设：

```
world_q = parent_world_q * local_q
world_p = parent_world_p + rotate(parent_q, rest_delta)
```

如果这个假设错了，脚踝高度就是错的，355 段接触、34.6% 覆盖率、
0.404 单位/帧滑步全都不可信。所以在写 M1 之前，必须先和 Blender 对一次。

## 2. 方法

Blender 5.2.2 + MMD Tools（扩展 `bl_ext.user_default.mmd_tools`）：

```bash
blender -b --python tools/blender_dump_pose.py -- \
  /root/mmd-vision/assets/model/薇斯纳.pmx \
  /root/mmd-vision/assets/motion/恋爱循环.vmd \
  /tmp/blender_pose.json
```

- 导入 PMX + VMD，采 17 个 VMD 帧（0、10、50 … 5639）；
- 每帧取 21 根骨在 armature space 的 `pose_bone.matrix.translation`；
- VMD 第 0 帧对应 Blender 第 1 帧（MMD Tools 的 `+1` 偏移）。

### 2.1 坐标系（第一个坑）

第一版按“(x, y, z) → (x, −z, y)”转换，结果肘/腕的 z 全部反号，
误差 16 个单位。真实映射是 MMD Tools 的 `_VectorXZY`：

```
PMX (x, y, z)  →  Blender (x, z, y)
```

这是左右手系之间的**反射**，不是旋转，三个分量都取正。改对后误差立刻
从“米级”降到“毫米级”。

**教训**：跨坐标系对比时，先拿 rest head 对一遍；rest 都对不上，不要
急着怀疑算法。

## 3. 结果

| 骨 | 误差中位数 | p95 | 最大 | 说明 |
|---|---|---|---|---|
| センター | 0.013 | 0.089 | 0.295 | |
| 上半身 / 首 / 頭 | 0.013 | 0.089 | 0.295 | |
| 肩 / 腕 / ひじ / 手首 | 0.013–0.037 | 0.09–0.11 | 0.295 | |
| 左足 / 右足（大腿） | 0.013 | 0.089 | 0.295 | |
| **左ひざ** | **1.255** | 2.733 | 3.185 | IK 驱动 |
| **左足首** | **1.446** | 5.498 | 5.621 | IK 驱动 |
| **左つま先** | **1.677** | 5.872 | 6.969 | IK 驱动 |
| 右腿 | 1.06–1.27 | 2.7–5.9 | 6.3 | IK 驱动 |

单位：PMX 单位，1 单位 ≈ 8.7 cm。

**非 IK 身体骨**：中位 **0.0133 单位（1.2 mm）**，p95 0.295（2.6 cm），
最大 0.295。p95 的误差集中在**非关键帧**：我们用 slerp/线性采样，
MMD 用贝塞尔插值。关键帧上误差接近 0。

**腿骨**：膝盖以下完全对不上，最大 6.97 单位（61 cm）。原因不是 FK 公式
错，而是 MMD 的腿由 `左足ＩＫ` / `右足ＩＫ` 的**IK 约束**驱动，VMD 里
腿骨本身的旋转键很少。用纯旋转 FK 去推脚踝，相当于忽略了 IK。

## 4. 修正：用足 IK 目标代替腿 FK

MMD 的 IK 骨位置就是脚踝目标：

```
ankle_world = rest_head(左足ＩＫ) + translation(左足ＩＫ)
```

对拍验证（Blender 实测脚踝）：

| 帧 | IK 目标 | Blender 脚踝 | 误差 |
|---|---|---|---|
| 0 | (0.009, 1.148, 0.138) | (0.011, 1.171, 0.136) | 0.023 |
| 500 | (0.959, 1.198, 3.638) | (0.958, 1.198, 3.639) | 0.001 |
| 3000 | (−0.642, 1.148, 1.102) | (−0.642, 1.148, 1.102) | 0.000 |

误差 0.1–2.3 mm，足够做接触检测。第 0 帧的 2.3 mm 来自采样/IK 残差。

`detect_contacts` 现在的策略：

1. 目标模型有 `leftFootIK`/`rightFootIK` 且 canonical 里有对应位移键
   → 用 IK 目标（`source: "foot_ik"`）；
2. 否则回退到纯 FK（`source: "fk"`），并在接触段里标明来源。

## 5. 修正后的接触统计

同一段动作：

| 指标 | 旧（腿 FK） | 新（足 IK） |
|---|---|---|
| 接触段 | 355 | **249** |
| 覆盖率 | 34.6% | **67.4%** |
| 段长 min/avg/max | 5 / 11 / 99 | 5 / 30.6 / 298 |
| 平均滑步 | 0.404 单位/帧 | **0.154 单位/帧** |
| 最大滑步 | 2.287 | 1.723 |

第一段是 0–297 帧（约 10 秒）的**站立前奏**：左脚平均滑步 0.008、
右脚 0.0001 单位/帧，基本不动。旧 FK 把它误判成两段 61 帧的“接触”，
因为腿骨旋转推出来的脚踝在抖。

67.4% 的覆盖率意味着大量时间双脚都接近地面，符合这支舞的重心切换；
但“接近地面”仍不等于“该锁”，M1 还要结合骨盆/另一只脚做承重判断。

## 6. 对 M1 的直接影响

1. **脚部轨迹以 IK 目标为准**，不要用腿骨 FK 推；
2. 脚锁可以直接改 `足IK` 的位移键，让目标模型自己的 IK 去弯腿；
3. 膝盖限位已经在目标模型的 IK 约束里，反关节问题交给 MMD/Blender；
4. 需要检查**可达性**：锁定位置到髋的距离不能超过大腿+小腿长度，
   否则 IK 会拉伸或滑步；
5. 非 IK 骨（脊柱、手臂）可以继续用 rest-relative 旋转重定向，
   1.2 mm 的中位误差在 M1 的 1 cm 验收线内。

## 7. 剩余风险

- 只有一段动作、一个人类模型，**无法做真正的跨模型验证**；M1 的
  比例适配只能用“缩放 profile”模拟；
- 足 IK 目标只在 VMD 含 IK 键时存在；纯 FK 腿的动作会走回退路径，
  精度回到“厘米级”；
- Blender 对拍只采了 17 帧，且是非连续帧；全帧对拍成本高（每帧
  `frame_set` + depsgraph），M1 可以按需扩到 100 帧；
- MMD Tools 的 IK 求解与 MMD 本体可能有细微差异，最终验收仍应以
  MMD 播放为准。
