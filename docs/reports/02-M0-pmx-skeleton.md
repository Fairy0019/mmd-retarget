## 1. PMX 读取器

解析范围（按 STEPS ② 的最小集）：

| 段 | 处理 |
|---|---|
| 文件头 | PMX 2.0 / 2.1 版本检查，8 个 globals，UTF-16LE / UTF-8 |
| 顶点 | 位置、法线、UV、附加 UV、BDEF1/2/4、SDEF、QDEF、边缘缩放 |
| 面 | 只统计三角形数，不保留索引 |
| 贴图 | 路径字符串 |
| 材质 | 名称、颜色段、贴图/sphere/toon 索引、面数 |
| 骨骼 | 名称、父级、layer、flags、tail、付与、轴固定、局部轴、外部亲、IK 链 |
| morph | 名称、panel、类型、offset 数量；offset 按类型正确跳过 |

所有 `count` 先做边界检查；负数和越界都会抛 `PmxError` 并带 offset。

### 1.1 真实模型结果

样本：`薇斯纳.pmx`（6,411,526 字节）

```

vertices   63,278
triangles  77,167
bones      550 (4 IK)
materials  38
morphs     67  (vertex 63 / material 3 / bone 1)
textures   27
```

骨骼抽检（模型空间绝对坐标）：

| 骨 | head | 长度 | 父 |
|---|---|---|---|
| センター | (0, 10.156, −0.460) | 8.914 | 全ての親 |
| 上半身 | (0, 12.322, −0.691) | 0.672 | 腰 |
| 左腕 | (1.129, 15.424, 0.078) | 2.592 | 左肩C |
| 左ひじ | (3.243, 13.926, 0.132) | 2.547 | 左腕捩 |
| 左足 | (0.951, 11.220, −0.481) | 4.943 | 腰キャンセル左 |
| 左ひざ | (0.642, 6.291, −0.291) | 5.172 | 左足 |
| 左足首 | (0.309, 1.148, 0.138) | 1.659 | 左ひざ |

IK 限位（左右膝）：

```
左ひざ / 右ひざ  min (-3.1416, 0, 0)  max (-0.0087, 0, 0)
```

即膝盖只能绕 X 轴向后弯，最大接近伸直。这个符号方向很关键：M1 的腿 IK
必须遵守，否则会出现反关节。

### 1.2 一个差点写错的格式细节

网上不少 PMX 说明把 bone flags 写成：

```
0x0040 回転付与 / 0x0080 移動付与 / 0x0100 軸固定 / 0x0200 ローカル軸
```

实际（以 MMD Tools 的 `Bone.load` 为准，并用真实文件验证）：

```
0x0100 回転付与
0x0200 移動付与
0x0400 軸固定
0x0800 ローカル軸
0x1000 物理後変形
0x2000 外部親
```

第一版按错误表解析，在 `左目`（flags `0x011A`）处把原本 6 字节的
「付与亲 + 比例」当成 12 字节的轴固定，导致后续 550 根骨全部错位。
真实模型里有 **46 根轴固定骨、4 根局部轴骨**，这个错误一定会被触发。

**教训**：格式文档要以“能解析真实文件”为准；解析器必须在第一个不合理的
字符串长度处立刻报错，而不是继续硬读——本次就是靠 `text()` 的长度检查
在 5,564,693 字节处定位到的。

## 2. skeleton profile

`python -m mmd_retarget.cli skeleton 薇斯纳.pmx -o profile.json`

```
bones     550
mapped    89/97 semantics (91.8%)
limits    2
colliders 19
size      179,643 bytes (JSON, 550 rest entries)
```

### 2.1 语义映射

命名约定：`leftUpperArm` / `leftLowerArm` / `leftHand` / `leftUpperLeg` /
`leftLowerLeg` / `leftFoot` / `leftToe`，左右前缀固定 `left` / `right`。
同时兼容 `腕.L` 这类后缀写法。

覆盖情况：

- 97 个语义键中命中 89 个；
- 未命中的 8 个：`spine3`、`leftEar`、`rightEar`、`leftToeD`、`rightToeD`、
  `rightLowerArmTwist1/2/3` —— 都是这个模型本身没有的骨，不是映射逻辑问题；
- 动作里实际出现的 140 根骨：**66 根映射到语义**；剩余 74 根**全部**是
  41 根 `〜先` 显示骨 + 48 根头发/裙/袖/领带/腰饰/目光骨（15 根重叠），
  **没有一根身体骨漏掉**。

### 2.2 碰撞体

按「权重 ≥ 0.5 的顶点包围盒」估计胶囊半径，公式：

```
r = 0.5 * sqrt(Δx * Δz)     # 几何平均，抗单个轴的离群拉伸
clamp(r, 0.05, 1.2)
```

结果（模型单位，1 单位约 8.7 cm）：

| 语义 | 骨 | 半径 |
|---|---|---|
| hips | 下半身 | 1.200 |
| spine1 | 上半身1 | 0.979 |
| spine2 | 上半身2 | 1.105 |
| neck | 首 | 0.480 |
| head | 頭 | 1.200 |
| leftUpperArm | 左腕 | 0.342 |
| leftLowerArm | 左ひじ | 0.355 |
| leftUpperLeg | 左足 | 0.906 |
| leftLowerLeg | 左ひざ | 0.682 |
| leftFoot | 左足首 | 0.646 |

腿部本体骨（左足/左ひざ/左足首）在这副模型上**没有直接权重**，蒙皮全在
D 骨（左足D/ひざD）上；半径因此回退到 D 骨的包围盒，胶囊端点仍用本体骨。
这是 MMD 模型的常见结构，不能假设“骨名存在 = 有权重”。

## 3. 漏洞与风险思考

### 3.1 PMX 的 tail 是“显示提示”，不是形变段

`センター` 的 tail 是 `head + (0, -8.914, 0)`，指向地面；`全ての親` 的
tail 又指向 `センター` 附近。MMD 只把它当骨骼显示终点，真正参与形变的是
父子 rest 偏移。

**约束**：M1 计算骨骼长度/碰撞段时，必须以「父 head → 子 head」为准；
profile 里的 `tail` 只作参考。当前碰撞体只对白名单身体骨使用 tail，
腿部已改用 D 骨包围盒，暂时绕开了这个坑。

### 3.2 PMX 没有 bone roll

profile 里 `roll: 0.0` 是占位，不是真实 roll。真正的 roll 必须在 Blender
里由 head/tail + local axis 计算。**不要**拿 profile 的 roll 去做 rest
适配，否则会引入系统性扭转。

### 3.3 胶囊半径只是初值

包围盒会把袖子、飘带、相邻部件的权重算进来。样本里 `右ひじ` 有 796 个
权重顶点（左ひじ只有 50 个），半径 0.71，明显偏大。M2 的穿透检测必须用
实际网格 BVH；这些胶囊只用于 M1 的“粗间隙约束”和 M3 的布料碰撞。

### 3.4 550 根骨里大部分不是身体骨

头发、裙、袖、翅膀、领带、腰饰都是物理/装饰骨。profile 保留全部 rest
（FK 需要），但重定向只能对 `map` 里的语义骨做；物理骨应交给 M3 的 PBD，
否则会把头发当身体去 IK，动作会僵硬。

### 3.5 同名骨

`Pmx.bone_by_name()` 用 dict，同名骨只保留最后一个。MMD 模型通常不允许
同名，但第三方改造模型可能出现。若真要支持，需要把 map 的值改成索引而
不是名字；这会波及 canonical / retarget 的接口，暂不做，但在 profile 里
记录了 `index` 顺序，后续可迁移。

### 3.6 PMX 2.1 / SDEF / QDEF 没有真实样本

解析器按规范实现了 SDEF（权重类型 3）和 QDEF（4），但样本只用了
BDEF1/2/4；morph 只出现了 vertex/material/bone 三种。剩余 7 种 morph
offset 只有合成测试覆盖。**风险**：规范里个别 offset 的字节数（尤其
impulse 的刚体索引宽度）可能与实现不一致。需要找 PMX 2.1 样本回归。

### 3.7 源动作与目标骨架的链长不一致

源 VMD 只有 `上半身`，目标模型有 `上半身 / 上半身1 / 上半身2` 三段。
M1 必须把源 `上半身` 的旋转按比例分配到目标链上，否则胸口会少一段弯曲，
手臂 IK 的起点会偏高。这不是 profile 能解决的问题，是 retarget 的核心
算法之一。

### 3.8 单位与缩放

profile 没有记录“1 单位 = 多少米”。当前所有阈值（脚锁 5mm、间隙 1.5cm）
都是米制，M1 必须先从 Blender 场景或模型身高推一个 `unit_scale`，
否则阈值会随模型大小漂移。建议在 profile 里加 `height` 与 `unit_scale`，
等 M1 接入 Blender 时一起做。
