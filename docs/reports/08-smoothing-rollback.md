# 阶段报告 08 · 时间平滑：一次被回滚的尝试

- 日期：2026-10-23
- 范围：`retarget.smooth_series` / `smooth_foot_lock`
- 结论：全局限速能把最大步长从 **2.74** 压到 **0.13 单位/帧**，但会把
  锁定窗口内部拖动 **0.97 单位（8.4 cm）**，直接破坏脚锁不变量。
  **默认关闭**，保留工具函数与测试，等锚定式平滑。

---

## 1. 问题

分窗脚锁（报告 06）把每个 20 帧窗口钉在各自均值上。相邻窗口的均值
可能差很多，边界处脚会瞬移：

```
max step = 2.744 单位/帧   （≈ 24 cm/帧，30fps 下不可接受）
```

## 2. 第一版方案

对整条足 IK 轨迹做：

1. 盒式平均（窗口 ±2 帧）；
2. 双向限速：每帧位移不超过 `0.01 m` 换算出的模型单位；
3. 写回逐帧键。

结果：

| 指标 | 平滑前 | 平滑后 |
|---|---|---|
| 最大步长 | 2.744 | **0.130** |
| 锁定窗口内部漂移 | ~0 | **0.973** |
| 整段平均滑步 | 0.1456 | 0.1132 |

最大步长达标了，但**锁定窗口内部漂移从 0 变成 8.4 cm**。也就是说，
脚在“应该钉死”的 20 帧窗口里又被平滑拉走了。这是不可接受的：脚锁的
全部意义就是窗口内不动。

## 3. 根因

限速是**全局序列**操作。一个 2.7 单位的跳变，在 0.13 单位/帧的限制下
需要 21 帧才能消化，而窗口只有 20 帧。前向/后向两遍会把修正“渗”进
相邻窗口的内部，常量段不再常量。

换句话说：

> 最大步长和窗口内漂移是一对矛盾。只看最大步长，可以把脚锁完全抹平
> 来“达标”；必须同时报告**不变量**。

## 4. 正确的做法（尚未实现）

1. **锚定式平滑**：锁定窗口内的帧是硬约束，不能改；只允许在窗口之间
   的未锁定段做过渡。
2. **邻窗一致性**：相邻窗口的锁定位置差超过阈值时，跳过其中一个，
   而不是靠平滑硬接。
3. **按差值决定过渡长度**：`n = ceil(delta / max_rate)`，只有未锁定段
   足够长时才做过渡；不够长就标记“不可平滑”，交人工。
4. **骨盆补偿**：很多跳变来自“脚够不到”，移动 root 比平滑脚更合理。
5. **修正量膨胀→平均→限速**（ARCHITECTURE 3.4）：对**修正量**做处理，
   而不是对最终位置，避免把未修正段也拖进来。

## 5. 决策

- `retarget.DEFAULT_CONFIG["smoothing"]["enabled"] = False`；
- `smooth_series` / `smooth_foot_lock` 保留，单测覆盖；
- CLI 不再宣称“平滑已接入”；
- 报告 06 的脚锁不变量（窗口内漂移 ~0）保持成立。

## 6. 测试

`pytest -q`：**69 passed**。新增：

- `smooth_series` 把阶跃限制到 `max_rate`，首尾仍收敛；
- `smooth_foot_lock` 能降低最大步长并返回统计。

这两个测试只验证工具函数本身，**不**证明它适合脚锁；报告里的 0.973
漂移就是反例。

## 7. 教训

1. **指标要成对**：脚锁必须同时看“最大步长”和“窗口内漂移”，否则
   优化一个必然牺牲另一个。
2. **默认关闭也是一种交付**：知道一条路走不通，并把原因写清楚，比
   留一个看起来能跑、实际会把脚拉走的开关更有价值。
3. **平滑的对象应该是修正量**，不是最终位置；这是 ARCHITECTURE 早就
   写对的，第一版实现偏离了它。
