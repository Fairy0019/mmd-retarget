# 阶段报告 18 · M1 stage 6 骨盆补偿

- 日期：2026-10-24
- 范围：`retarget._apply_pelvis_compensation`、CLI 骨盆统计
- 结论：53 个“够不到”的窗口里，**38 个**通过移动 root 变得可达并成功锁定；
  最大 root 位移 48 mm，限速 8 mm/帧，残留 1 个窗口。

---

## 1. 口径：脚和骨盆不在同一个坐标系里

这是报告 16 只做诊断的原因：

- 脚 IK 的目标 = `足IK rest head + 足IK 位移`，**不含 root**；
- 髋关节 = `forward_positions(...)`，**含 root**。

所以：

```
移动 root  →  骨盆动，脚不动
```

这正是骨盆补偿需要的行为。之前担心“移动 root 会让脚跟着动”，是把
canonical 的位移误当成了世界坐标；实际足 IK 親挂在 `全ての親` 下，
不在 `センター` 下。

## 2. 算法

1. 脚锁阶段遇到 `髋→脚 > 腿长` 的窗口时，不立即跳过，而是记录：
   - 窗口区间、锁定位置、髋位置、腿长、需要的位移 `deficit`；
2. 若 `deficit <= max_shift_m`（默认 8 cm），把 root 朝脚的方向移动
   `deficit`，让髋落到腿长 98% 的位置；
3. 多个窗口重叠时取平均；
4. 对 root 位移做 ±2 帧盒式平滑 + **8 mm/帧限速**（前后各一遍）；
5. 用新的 root 重新算髋位置，复检每个候选：
   - 可达 → 写入足 IK 常量键，加入 `locked_chunks`；
   - 仍不可达 → 记 `pelvic_residual`，跳过（不硬拉）。

所有位移都在目标模型单位下计算，米制阈值按身高换算。


## 5. 漏洞与风险

### 5.1 移动 root 会改动作

骨盆补偿不是“免费的”：它把角色整体朝支撑脚方向挪，可能改变编舞的
重心和观感。当前上限 8 cm、限速 8 mm/帧，仍然可能被看出来。最终是否
接受应由人看渲染决定；报告只保证“脚够得到”。

### 5.2 只补偿支撑脚

一个窗口的 root 位移会影响另一只脚的可达性。当前只在补偿后复检被补偿
的窗口本身，没有全局复检另一只脚。残留 1 个窗口可能就是这么来的。
下一步应该做“双足联合约束”：同时满足两只支撑脚，求最小 root 位移。

### 5.3 没有和 Blender 对拍

补偿后的 root 位移是否被 MMD 正确应用、脚是否真的落到目标，还需要用
`blender_dump_pose.py` 对拍。当前只验证了 canonical 几何。

### 5.4 53 → 38 的剩余

15 个窗口仍然跳过：

- 其中 1 个是补偿后仍不可达（residual）；
- 其余是 `deficit > 8 cm`，超过安全上限。

这些要么是源动作本身在挑战腿长，要么需要“抬脚/改舞步”，不应由工具
静默硬拉。
