# 阶段报告 06 · M1 stage 1 比例缩放与脚锁

- 日期：2026-10-23
- 范围：`src/mmd_retarget/retarget.py`、CLI `retarget`、`tests/test_retarget.py`
- 结论：脚锁在**被判定为可锁的窗口**内把漂移压到 **1e-16 单位**；
  但只有 26.8% 的接触帧满足“可锁”条件，M1 还没完成。

---

## 1. 做了什么

| 能力 | 实现 |
|---|---|
| 比例 | `scale = 目标身高 / 源身高`，缩放 root 与所有位移轨 |
| 语义重映射 | 按 profile 的 `map` 把 canonical 写到目标骨 |
| 脚锁 | 接触段按 20 帧切窗；窗口内脚目标钉在均值 |
| 防误锁 | 窗口内源脚漂移 > 4 cm 判为“迈步”，跳过 |
| 可达性 | 用每帧 FK 髋位置检查髋→脚距离；超过腿长则跳过并报告 |
| 统计 | 锁定窗口、锁定帧覆盖率、跳过原因、最大可达比 |

关键取舍：

- **不硬拉**。可达性失败默认 `clamp_unreachable=false`，跳过而不是把脚
  拽到腿长以内。强行拉会让脚离地/穿地，比不锁更糟。
- **切窗**。真实动作的“接触段”可以长达 298 帧（10 秒站立），整段锁到
  均值会把慢速移动也抹掉；20 帧窗口能跟上身体重心变化。
- **漂移阈值用米**。`max_lock_drift_m = 0.04`，按目标身高换算成模型单位
  （假设角色 1.6 m）。

## 2. 真实动作结果（同模型，scale = 1.0）

```
contacts          : 249
chunks            : 493
locked            : 189  (38.3% 的窗口)
locked frames     : 3,026 / 11,280  (26.8%)
contacts with ≥1 locked chunk : 94 / 249
skipped (drift)   : 255
skipped (reach)   : 49
clamped           : 0
max reach ratio   : 1.234
```

锁定窗口内的漂移：

```
max drift = 1.11e-16 单位   （浮点误差，等价于 0）
```

源动作整段滑步：

```
mean slide : 0.1541 -> 0.1456 单位/帧
```

**为什么整段滑步几乎没降？** 因为 255 个窗口被判为“迈步”没有锁，
它们仍保留源动作的滑步；`contact_slide_stats` 统计的是整个接触段。
真正该看的是“锁定窗口内漂移 = 0”，以及锁定覆盖率 26.8%。

## 3. 为什么 49 个窗口不可达

同模型、scale=1 仍然有 49 个窗口髋→脚距离超过腿长。原因：

1. 源动作在接触帧常把腿伸到接近完全直（rest 腿长就是 5.0，髋到脚 4.9）；
2. 脚目标只要横向偏 0.1，距离就超过 5.0；
3. MMD 的 IK 允许轻微拉伸/误差，我们的几何检查更严格。

这不是 bug，而是“源动作本身在挑战腿长极限”。M1 stage 2 的骨盆补偿
应该在这些帧把骨盆向支撑脚方向移动，而不是跳过。当前先报告。

## 4. 一个测试暴露的设计问题

合成测试里，rest 姿势是**完全直腿**（髋-膝-踝共线），任何脚部偏移都会
触发“不可达”。这提醒我们：

- 可达性必须用**每帧 FK 髋位置**，不能用 rest 髋；
- 阈值要允许 1–2% 的数值余量，否则直腿站立会被误判；
- 测试骨架要带一点膝盖弯曲，否则测的是“几何奇点”而不是算法。

现在测试骨架的膝盖向外偏 0.5，腿长 5.1、髋踝距离 5.0，留出 2% 余量。

## 5. 漏洞与风险

### 5.1 只锁了 26.8% 的接触帧

其余帧分两类：

- **迈步**（255 窗口）：脚在地面附近但水平移动大，不该锁；
- **不可达**（49 窗口）：需要骨盆补偿。

M1 的“滑步 < 5 mm”验收不能只看锁定窗口，必须定义**承重段**：
一只脚锁定时，另一只脚在迈步；双脚都“贴地”时至少一只承重。
当前没有承重判断，覆盖率偏低是保守策略的代价。

### 5.2 窗口边界会跳

每个 20 帧窗口独立取均值，相邻窗口的锁定位置可能差几厘米，边界处
脚会瞬移。M1 stage 3 的时间平滑（膨胀→平均→限速）必须作用在**锁定
位置序列**上，而不是只平滑旋转。

### 5.3 旋转还是 pass-through

本阶段只做了比例和脚锁，语义旋转原样复制。源/目标 rest、roll、链长
差异都没处理，所以：

- 手臂末端位置仍会随体型漂移；
- 源 `上半身` 不会分配到目标 `上半身1/2`；
- 换模型时“整体偏内 3°”的系统误差仍在。

这是 M1 stage 2 的核心，不应把本阶段的输出当成可用重定向结果。

### 5.4 没有真正的跨模型验证

本地只有一个人类模型（薇斯纳）。比例逻辑只用“缩放 profile”做过单测，
没有第二副真实骨架。**这是 M1 最大的验证缺口**。需要至少一个不同体型
的 PMX（最好身高差 20% 以上）才能验收“末端误差 < 1 cm”。

### 5.5 米制换算靠假设

`1.6 m / 身高` 是粗估。若模型是 Q 版（身高 10 单位），4 cm 阈值会被
换算成更大的模型单位，锁定行为会变。M1 应该从 Blender 场景或模型
元数据拿真实身高。

### 5.6 脚 IK 缺失时的回退

纯 FK 腿的动作没有 `足IK` 位移键，`skipped_no_ik` 会上升，脚锁完全
不生效。这类动作需要直接对腿骨做 IK 烘焙，属于 stage 2/3。

## 6. 测试

`pytest -q`：**64 passed**。本阶段新增 7 个：

- 身高比例；
- root / 位移缩放；
- 窗口内锁定为常量；
- 锁定后窗口漂移 = 0；
- 高漂移窗口不锁；
- 不可达窗口 clamp / skip；
- 目标缺 IK 骨时跳过。

## 7. 下一步（M1 stage 2）

1. **rest-relative 旋转重定向**：世界旋转增量 + 目标局部化；
2. **脊柱链拆分**：源 `上半身` → 目标 `上半身/1/2`；
3. **骨盆补偿**：不可达时移动 root，而不是跳过；
4. **承重判断**：用骨盆投影 + 另一只脚状态决定锁哪只脚；
5. **手臂 IK + 间隙**：目标手腕轨迹、极向量、胶囊约束；
6. 找第二副体型差异明显的 PMX 做跨模型验收。
