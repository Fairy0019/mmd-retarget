# 阶段报告 12 · M2 stage 2 可见性判定

- 日期：2026-10-24
- 范围：`validate_blender._setup_camera` / `_visible`、CLI `--visibility`
- 结论：**可见性已接入**。1,051 条记录里 288 条可见，其中 37 条 high
  全部是“腿穿出裙子外层”；手臂–躯干的重叠大多被遮挡。

---

## 1. 做法

1. 有 `--camera NAME` → 用场景里同名相机；
2. 没有 → 创建一个正面偏上的默认机位（只为演示“能不能看见”，
   不是最终机位）；
3. 对每条记录，取产生最大深度的那个顶点 `P`；
4. 从相机原点向 `P` 发射射线：
   - 第一个命中点就在 `P` 附近（< 1% 身高）→ `visible=yes`；
   - 命中点明显更近 → 被其他几何遮挡 → `visible=no`；
5. CSV 的 `visible` 列写 `yes` / `no` / `unknown`。

注意：射线打的是“最深顶点”，不是整个穿透区域。它回答的是“这个点
能不能被相机直接看到”，不是“穿透区域有多少像素可见”。后者需要
深度缓冲/多采样，属于下一 stage。

## 2. 源动作结果

采样 282 帧，耗时 **31 s**（比无可见性多 7 s）：

```
records : 1,051
visible : yes 288 / no 763
severity: high 52 / medium 572 / low 427
```

severity × visible：

| | yes | no |
|---|---|---|
| high | **37** | 15 |
| medium | 91 | 481 |
| low | 160 | 267 |

**37 条可见 high 全部是腿–裙子**：

| frame | 部位 | 深度 |
|---|---|---|
| 4100 | leftLeg–skirt | 67.96 mm |
| 3020 | rightLeg–skirt | 64.91 mm |
| 1040 | leftLeg–skirt | 63.19 mm |
| 3280 | rightLeg–skirt | 62.03 mm |
| 2180 | rightLeg–skirt | 61.80 mm |

手臂–躯干的重叠最大 31 mm，但绝大多数被判为 `no`：手臂在袖子里/身体
后面，最终机位看不到。这符合直觉，也说明**只按深度定级会高估问题**。

## 3. 解读

1. **视觉优先级**：裙子是当前最明显的穿模来源，正好对应 M3 的被动件
   物理；M1 的手臂 IK 虽然深度不小，但多数被遮挡。
2. **隐藏穿透仍然要修**：`no` 不代表不存在，换机位/换动作就可能露出来。
   报告保留 `no` 记录，只是不把它们排到 high 前面。
3. **默认机位不是验收机位**：真实验收必须传最终相机名。默认机位只
   用于自动化冒烟测试。

## 4. 漏洞与风险

### 4.1 单点射线，不是像素覆盖

只测“最深顶点”。穿透区域边缘可能可见而最深点不可见，反之亦然。
下一 stage 应对穿透三角形的多个采样点做射线，统计可见比例。

### 4.2 默认机位会误导

默认相机是正面偏上，和最终舞蹈机位（可能俯视/侧视/近景）差别很大。
**报告里的 `visible=yes/no` 只对所用相机有效**，必须把相机名写进
报告元数据（当前 CSV 没有这一列，需补）。

### 4.3 自遮挡

射线可能被同一部位（例如裙子的另一层）挡住，判为 `no`，但视觉上
仍可能从缝隙看到。需要区分“被自己挡住”和“被其他部位挡住”。

### 4.4 衣物法线

腿–裙的 `outside_is_bad` 判据依赖裙面法线。当前样本上可见 high 都是
腿穿出裙子，结果合理；但换一套双面材质/法线翻转的模型可能失效。

### 4.5 没有缩略图

37 个可见 high 帧需要人工确认。下一步应渲染 320×320 缩略图或
contact sheet，否则验收仍要手动跳帧。

## 5. 用法

```bash
blender -b --python tools/blender_cli.py -- validate \
  --model model.pmx --motion motion.vmd \
  -o report.csv --step 20 --visibility --camera final_cam
```

## 6. 测试

- 纯 Python：75 passed（可见性逻辑在 Blender 端，无单测）；
- 真实数据：6 帧冒烟 + 282 帧全量，均跑通；
- 可见性开启后耗时 24 s → 31 s（+29%）。
