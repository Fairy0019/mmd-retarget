# 阶段报告 03 · M0-④ / ⑨ canonical motion 与 writer

- 日期：2026-10-23
- 范围：`src/mmd_retarget/canonical.py`、`src/mmd_retarget/writer.py`、CLI `inspect --out` / `retarget`
- 结论：**VMD → canonical → VMD 闭环成立**。同骨架 round-trip 的 25,973
  个关键帧、2,344 个 morph 帧全部数值一致；换骨架时按语义映射自动裁剪。

---

## 1. canonical motion 结构

```jsonc
{
  "schema": 1,
  "fps": 30,
  "frames": 5640,
  "source": {"model": "初音ミク", "vmd": "...", "profile": "..."},
  "root": {
    "pos": [[0, 0, 0, 0], ...],          // センター 的位移
    "rot": [[0, 0, 0, 0, 1], ...]        // センター 的旋转
  },
  "joints": {
    "leftUpperArm": [[0, 0, 0, 0, 1], ...]
  },
  "translations": {
    "leftFootIK": [[0, 0.1, 1.2, 0], ...]
  },
  "extra": { "ﾈｸﾀｲ１": [[0, 0, 0, 0, 1], ...] },
  "extra_translations": { "左袖": [[0, 0, 0, 0], ...] },
  "contacts": [
    {"start": 0, "end": 61, "effector": "leftFoot",
     "pos": [-0.17, 0.83, 0.12], "min_y": 0.74,
     "mean_slide": 0.07, "max_slide": 0.14, "threshold": 1.56}
  ],
  "morphs": { "まばたき": [[0, 0.0], [10, 1.0]] },
  "meta": {"joints": 65, "extra_bones": 74, "contacts": 249, ...}
}
```

与 `docs/ARCHITECTURE.md` 原稿的差异：

1. `root` 拆成 `pos` / `rot` 两个列表——VMD 里两者的关键帧时刻经常不同，
   强行合成一条会引入重采样误差；
2. 增加 `extra` / `extra_translations`：没有语义映射的物理骨原样透传，
   保证同模型 round-trip 不丢头发/裙/袖；
3. 增加 `contacts` 的 `mean_slide` / `max_slide`：把源动作的滑步量显式
   量化，而不是在检测阶段用速度阈值把它藏掉。

## 2. 关键帧清洗

真实文件 `恋爱循环.vmd` 的统计：

| 项 | 数值 |
|---|---|
| 骨骼关键帧 | 25,973 |
| 存在**乱序**帧的骨骼 | **55 / 140** |
| 重复帧 | 0 |

VMD 不要求文件内按帧号有序。`canonical` 对每根骨排序；重复帧保留
**最后一个**（MMD 的实际行为），并在 `meta` 里不做额外标记。

## 3. 接触段检测

M0 的检测器：

1. 只对 `profile.map` 里的 `leftFoot` / `rightFoot` 做 FK；
2. 旋转按 `world = parent_world * local` 复合，忽略 bone roll；
3. 用 ±12 帧的**局部最低点** + `0.02 × 身高` 作为贴地判据；
4. 不用速度做硬性否决——源动作本来就在滑，速度是**结果**不是前提；
5. 连续段允许 3 帧断裂，短于 5 帧的段丢弃。

真实动作结果（**已按报告 05 修正为足 IK 轨迹**）：

```
contact segments : 249（左 125 / 右 124）
coverage         : 67.4% 的“脚-帧”
segment length   : min 5 / avg 30.6 / max 298 帧
mean slide       : 0.154 单位/帧（段内平均）
max slide        : 1.723 单位/帧
```

**解读**：第一段是 0–297 帧的站立前奏（平均滑步 0.008 / 0.0001 单位/帧），
基本不动。其余段平均滑步 0.154 单位/帧 ≈ 4.6 单位/秒 ≈ 0.4 m/s。
源 VMD 没有脚锁，所谓“接触”只是脚离地面近，并不是真正钉在地上；
M1 的脚锁会把这些段锁到世界坐标。

> 完整推导见 `docs/reports/05-fk-validation.md`：腿骨是 IK 驱动的，
> 用纯旋转 FK 会把脚踝算错最多 61 cm，必须用 `足IK` 的位移键。

## 4. writer 与 round-trip

### 4.1 同骨架（构造完整 profile）

用动作里出现的 140 根骨构造一个 rest 占位 profile（只为验证数据层），
`detect=False`：

| 指标 | 结果 |
|---|---|
| 关键帧 | 25,973 → 25,973，**集合完全一致** |
| 最大旋转误差 | **0.000003°** |
| 最大位移误差 | **0.000000** |
| morph 帧 | 2,344 → 2,344 |
| canonical 构建 | 0.09 s |
| writer | 0.13 s |

旋转误差来自 float32 存储（VMD 本身是 float32），远低于 0.1° 验收线。

### 4.2 换骨架（初音ミク → 薇斯纳）

| 指标 | 结果 |
|---|---|
| 写出骨骼数 | 77（66 语义 + 11 同名 extra） |
| 写出关键帧 | 23,266 / 25,973（89.6%） |
| 丢弃 | 63 根目标模型没有的物理/显示骨，2,707 帧 |
| morph | 31 个源 morph 全部在目标模型找到同名 |
| canonical 构建（含接触） | 0.54 s |
| writer | 0.18 s |
| canonical JSON | 1.7 MB |

被丢弃的 63 根骨全部是 `左髪*`、`右ｽｶｰﾄ*`、`ﾈｸﾀｲ*`、`〜先` 等
物理/显示骨。这与 M0 的定位一致：M1 只重定向身体；物理件由 M3 重新模拟，
而不是把源模型的头发动作硬套到目标模型。

## 5. 漏洞与风险思考

### 5.1 根运动只认 センター（高优先级）

`root` 固定取 `profile.map["root"]`，也就是 `センター`。如果某段动作把
位移打在 `グルーブ` / `全ての親` 上，这些位移会进 `extra`，换骨架时
直接丢失，表现为“角色原地踏步”。

样本动作只用 `センター`，所以没暴露。**M1 必须支持多根骨**（或至少在
canonical 里把 `グルーブ` 的位移合并进 root）。验证方法：找一段用
`グルーブ` 的 VMD，对比脚的世界轨迹。

### 5.2 0 位移关键帧被吞掉（已修）

第一版只在位移非零时记录 root 位置键。结果：`センター` 第 0 帧的位置
键（0,0,0）被丢掉，writer 采样时把第一段非零位移外推到第 0 帧，产生
**0.4 单位的假位移**。

修复：先扫描出“有位移的骨”，对这些骨保留**全部**位置键（包括 0）。
这类 bug 不会让程序崩溃，只会让角色整体偏移，属于最难靠单测发现的
“数值正确性”问题。现在的 round-trip 用“逐帧位置误差 = 0”专门盯它。

### 5.3 接触检测的 FK 是简化模型

- 忽略 bone roll：MMD 的局部旋转是否严格按 `parent_world * local` 复合，
  取决于模型 rest 朝向；本实现假设 rest 为单位朝向。
- 忽略 VMD 贝塞尔插值：采样用 slerp/线性，接触段边界可能差 1–2 帧。
- 只算到脚踝的链，不做全骨架 FK。

因此 `contacts` 只能作为 M1 的**初值**。M1 必须在 Blender 里用真实的
pose matrix 重算脚踝高度，再决定锁定区间。

### 5.4 “贴地”不等于“该锁”

当前 249 段里有大量段是“脚很低但在移动”（数字已按报告 05 修正）。如果 M1 无条件锁定，会把
本应迈步的帧钉住，产生“拖脚”。M1 需要：

1. 用脚踝**水平速度**做二次筛选（但阈值要按目标体型和 fps 定）；
2. 对每段做“是否真的承重”的判断（另一只脚是否抬起、骨盆是否在支撑侧）；
3. 锁定失败时回退到“不锁”，并在报告里标记，而不是硬锁。

### 5.5 插值曲线没有进 canonical

canonical 只存关键帧值，writer 统一写线性插值。数值在关键帧上完全一致，
但关键帧之间的曲线形状会变。对 30fps 的密集动作影响小，对稀疏的 IK /
表情曲线可能有可见差异。M1 若需要，可把 4 条贝塞尔曲线作为可选字段
`interp` 存进来（每帧 4×4 字节），代价是 JSON 体积增加约 40%。

### 5.6 morph 靠日文同名匹配

31 个源 morph 恰好都能在目标模型找到同名。换模型时常见 `まばたき2`、
`ウィンク右` 之类的变体，精确匹配会漏。M1 需要一张 morph 映射表
（可自动 + 人工确认），并在报告里列出未匹配项，而不是静默丢弃。

### 5.7 跨模型丢骨是“设计”不是“bug”

63 根物理骨被丢弃后，目标模型自己的头发/裙骨保持 rest 姿态。M0 的输出
看起来会“衣服不动”；这是预期的，M3 才做被动件物理。不要在本阶段用
“把源物理骨旋转按名字硬套”的方式糊弄——名字和层级都对不上，会炸。

### 5.8 JSON 体积

1.7 MB / 188 秒。全骨架 5640 帧约 3 MB。可接受；若将来要存 1 小时动作，
应改二进制（npz）或分块。当前优先可读性。

## 6. 测试

`pytest -q`：**56 passed**。本阶段新增：

- 乱序 + 重复帧清洗（后者胜出）；
- root 位置保留 0 值键；
- 四元数乘法/旋转/slerp；
- 稀疏采样端点保持；
- 合成骨架的接触段检测（贴地 → 抬起 → 贴地）；
- canonical JSON 往返；
- writer 同骨架数值一致、跨骨架丢 extra、morph 过滤、输出可被 VMD 解析；
- CLI `inspect --out` 与 `retarget` pass-through。
